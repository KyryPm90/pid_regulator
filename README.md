# FPV PID Тюнер

Веб-застосунок, який підбирає стартові PID і фільтри Betaflight для великих FPV-бортів (8–21", пропи від 7 до 24 дюймів), а після польоту коригує їх за Blackbox-логом.

## Що вміє

1. **Стартовий тюн.** Вводите діаметр і крок пропа, лопаті, тип рами, статор, KV, кількість банок, злітну вагу, стиль польоту і наявність RPM-фільтра. Застосунок рахує PID, FF, D min, фільтри гіроскопа й D-term, динамічний режекторний фільтр, RPM-фільтр, TPA, anti-gravity, rate-профіль (Actual rates, газ висіння, експо газу, обмеження газу) та видає готовий CLI. Стилів польоту п'ять: плавний (зйомка), вантаж, лонг-рейндж, агресивний (базовий) і швидкий. Під вибраним стилем видно, які значення він змінив порівняно з базовим.
2. **Корекція за Blackbox.** Завантажуєте лог прямо з польотника (`.bbl`, `.bfl`, `.txt`) або CSV з Blackbox Explorer чи `blackbox_decode`. Застосунок:
   - оцінює відгук на крок по кожній осі (деконволюція Вінера, як у PIDtoolbox): перерегулювання, затримку, дзвін, точність утримання;
   - будує спектр шуму гіроскопа до і після фільтрів;
   - знаходить резонанс рами (пік, що не рухається з газом) і шум моторів (пік, що росте з газом);
   - рахує, скільки часу мотори впираються в максимум;
   - автоматично налаштовує фільтри: LPF гіроскопа й D-term за залишковим шумом, `rpm_filter_min_hz` і кількість гармонік за частотами моторів, динамічний режекторний фільтр під резонанс рами (або під шум моторів без RPM-фільтра);
   - автоматично налаштовує рейти: `thr_mid` за газом висіння, знижує максимальні рейти, якщо мотори впираються в межу, і підказує, наскільки використано рейти;
   - пропонує зміни PID (не більше 15% за ітерацію) і новий CLI.

Файл логу обробляється тільки в браузері, на сервер нічого не відправляється.

3. **Запис у польотник по USB.** У Chrome або Edge на комп'ютері застосунок підключається до польотника (Web Serial), заходить у CLI Betaflight, показує різницю між поточними і новими значеннями і після підтвердження записує їх з `save`. Якщо прошивка відхилить хоч одну команду, нічого не зберігається.
4. **Офлайн (PWA).** Застосунок можна встановити на телефон чи ноутбук і користуватися ним без інтернету.
5. **Гараж і історія тюнів** (потрібен бекенд). Збережені борти і всі тюни з CLI, змінами і підсумком аналізу логу. Без бекенду ця панель просто прихована.

## Як записати лог

- Blackbox rate 1–2 кГц, увімкнений запис `gyroUnfilt`.
- 1–2 хвилини польоту з різкими нахилами по крену й тангажу, поворотами та змінами газу.
- Скопіюйте файл з SD-карти або скачайте з флешу через Configurator (вкладка Blackbox → Save flash to file) і завантажте його як є. Якщо у файлі кілька сесій (кілька армів), береться найдовша.
- Корекція рахується від налаштувань, з якими записано лог (Betaflight пише їх у заголовок), а якщо зчитати польотник по USB, то від поточних значень на ньому.
- Наступний завантажений лог автоматично порівнюється з попереднім: видно, що стало краще, а що гірше.
- Для важких бортів лог також перевіряється на коливання на високому газі (TPA), провали кута при різкому газі (anti-gravity) і просідання батареї (vbat_sag_compensation). Для останнього в лозі має бути напруга, тобто на польотнику має бути налаштований датчик напруги.
- CSV з Blackbox Explorer теж працює.

## Розробка

Монорепозиторій на npm workspaces:

- `packages/core` — модель тюну, генерація і розбір CLI, аналіз Blackbox. Один код для браузера і сервера.
- `apps/web` — веб-застосунок (Vite + TypeScript), PWA, Web Serial.
- `apps/api` — бекенд (Fastify + PostgreSQL).

```bash
npm install
npm run dev          # веб на http://localhost:5173, запити /api проксуються на :8787
npm run dev:api      # API; без DATABASE_URL дані зберігаються в пам'яті
npm test             # тести ядра, вебу і API
npm run build        # перевірка типів і збірка вебу в apps/web/dist
docker compose up    # API + PostgreSQL
```

Інтеграційний тест PostgreSQL запускається, якщо задано `TEST_DATABASE_URL`.

### API

Поки немає акаунтів, дані прив'язані до випадкового UUID браузера в заголовку `X-Client-Id`. Це не захист, а тимчасова ідентифікація; акаунти — наступний крок.

| Метод | Шлях | Що робить |
|---|---|---|
| GET | `/api/health` | стан і тип сховища |
| POST | `/api/tune` | розрахунок тюну і CLI за параметрами борта |
| GET, POST | `/api/builds` | список і створення бортів |
| GET, PUT, DELETE | `/api/builds/:id` | борт |
| GET, POST | `/api/builds/:id/sessions` | історія тюнів борта |

Змінні середовища: `DATABASE_URL`, `PORT` (8787), `CORS_ORIGIN` (через кому). Міграції застосовуються при старті або `npm run migrate -w @pid/api`. Для вебу адресу API задає `VITE_API_URL` під час збірки.

## Обмеження

Модель евристична і дає стартову точку, а не фінальний тюн. Перед першим зльотом перевірте напрямок моторів без пропелерів, зробіть 30 секунд висіння на малій висоті і перевірте нагрів моторів. Для 13" і більше перший зліт краще робити на прив'язі.
